This gallery fits the same six graph families as the multiscale GRIP gallery, using SGD metric MDS. Graphs, edge lengths and seeds are retained so their representations are easy to compare. This is an illustration, not a controlled benchmark of optimizer quality or runtime. All SGD fits here use three dimensions; the preserved GRIP tree example uses two.

Installed figures use static projections. To enable 3D rotation and layout selection, render with options(grip.vignette.interactive = TRUE) and ivue and rgl installed.

Each fit uses weighted graph shortest-path distances, uniform pair weights, and full metric MDS with the SGD backend. The examples are small enough for full distances. No edge-KK refinement follows MDS. For larger graphs see sparse SGD.

The reference coordinates generate edge lengths; they are not the MDS targets. Shortest-path distances need not admit an exact Euclidean representation, so a fitted layout can differ from the reference geometry even with low stress. The ivue viewers support rotation, zoom and selection of displayed geometries. Coordinates are centered for display without rotation or scale fitting; these are not aligned shape-recovery comparisons. The parameter grid is planar and is displayed at z = 0. Install ivue and rgl to build the interactive views.

library(grip)

Lifted lattices

The simplest geometry-rich family keeps the graph topology of a rectangular mesh but induces edge lengths from a curved embedding in R^3.

mesh.graph <- mesh.surface.graph(
  5, 5,
  surface = "saddle",
  amplitude = 0.8
)

mesh.fit <- metric.mds(
  edges = mesh.graph$edges,
  n = mesh.graph$n,
  edge.weights = mesh.graph$edge_weights,
  dim = 3,
  seed = 1,
  backend = "sgd", pair.weights = "uniform",
  max.iter = 1000, diagnostics = FALSE
)
#> Warning: Selected metric.mds() start terminated with iteration_limit; budget
#> exhaustion does not certify convergence; inspect metadata$starts
mesh.coords <- mesh.fit$coords

mesh.summary <- data.frame(
  family = mesh.graph$family,
  surface = mesh.graph$surface,
  n = mesh.graph$n,
  m = nrow(mesh.graph$edges),
  weight_scale = mesh.graph$weight_scale
)

knitr::kable(mesh.summary, digits = 3)

documentation.view(
  list(`SGD metric MDS`=mesh.coords,
       `Reference geometry`=mesh.graph$coords_surface,
       `Parameter grid`=cbind(mesh.graph$coords_param, z=0)),
  edges=mesh.graph$edges, aligned=TRUE,

The useful design pattern here is that the topology stays simple while the metric geometry becomes nontrivial.

Recursive and fractal families

Intrinsic weighted trees

Some family geometries are intrinsic rather than ambient. The weighted tree helpers preserve the exact tree topology while assigning edge lengths directly from branch-depth and branch-position rules.

tree.graph <- kary.tree.weighted.graph(
  k = 2,
  depth = 4,
  depth.rule = "geometric",
  depth.decay = 0.82,
  branch.rule = "linear",
  branch.spread = 0.25
)

tree.fit <- metric.mds(
  edges = tree.graph$edges,
  n = tree.graph$n,
  edge.weights = tree.graph$edge_weights,
  dim = 3,
  seed = 6,
  backend = "sgd", pair.weights = "uniform",

)

Stopping status

The table records each fit’s starts. An iteration-limit warning means that coordinates were returned without meeting the stopping criterion; it does not establish convergence or an optimum. Assess graph-distance error and stability across starts before interpreting a layout as evidence about geometry.

fits <- list(Saddle=mesh.fit, Torus=torus.fit, Vicsek=vicsek.fit,
             Annulus=annulus.fit, Porous=cube.fit, Tree=tree.fit)
for (name in names(fits)) {
  cat("\n\n### ", name, "\n\n", sep="")
  print(knitr::kable(fits[[name]]$metadata$starts, digits=5))
}
